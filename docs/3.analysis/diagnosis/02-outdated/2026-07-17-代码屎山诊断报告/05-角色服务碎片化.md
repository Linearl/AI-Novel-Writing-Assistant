## 二、数据流分析

### 2.1 角色生命周期

```
创建 (character/generate)
  │
  ▼
准备 (characterPrep/castGeneration)
  │
  ▼
阵容确定 (characterPrep/castQuality + castApply)
  │
  ▼
资源分配 (characterResource/extraction + ledger)
  │
  ▼
画像生成 (characterProfile/visibleProfile)
  │
  ▼
弧线管理 (characters/arc)
  │
  ▼
一致性检查 (characterConsistency/detector)
  │
  ▼
退场处理 (characterExit)
```

**问题**：生命周期的每个阶段都在不同目录，但阶段间的数据传递没有统一的 DTO/接口层。

### 2.2 序列化碎片化

11 个文件各自实现角色数据的格式转换：

| 文件 | 序列化内容 |
|------|-----------|
| `characterPrepHelpers.ts` | 角色准备数据 → prompt 格式 |
| `characterPreparationSupplemental.ts` | 补充角色数据映射 |
| `BookAnalysisCharacterSerializers.ts` | 角色 → 书籍分析格式 |
| `charactersTxtSerializer.ts` | 角色 → TXT 导出格式 |
| `characterHardFacts.ts` | 角色硬事实提取 |
| `characterConsistency/detector.ts` | 角色一致性检测格式 |
| `characterConsistency/extractor.ts` | 角色信息提取格式 |
| `characterCastApply.ts` | 阵容应用数据转换 |
| `characterCastGeneration.ts` | 生成数据格式 |
| `novelCoreCharacterService.ts` | 核心角色服务格式 |
| `CharacterResourceExtractionService.ts` | 资源提取格式 |

每个文件独立定义角色数据的字段映射，没有统一的 `CharacterDTO` 或 `CharacterMapper`。

## 三、Prompt Governance 违规

角色相关代码是 Prompt Governance 违规的重灾区：

| 文件 | 内联 prompt 数 |
|------|----------------|
| `characterPreparationSupplemental.ts` | **13 处** |
| `novelCoreCharacterService.ts` | 6 处 |
| `characterConsistency/detector.ts` | 2 处 |
| `characterConsistency/extractor.ts` | 2 处 |

这 23 处内联 prompt 应迁移到 `prompting/` 体系。

---

## 四、根因

| 根因 | 证据 |
|------|------|
| 功能按阶段而非按领域组织 | 每个阶段（准备/资源/画像/弧线/一致性）独立建目录 |
| 缺少角色领域层 | 没有统一的 Character Domain Service |
| Prompt 治理执行不严格 | 23 处内联 prompt 散落在 service 文件中 |

---

## 五、建议方案

### 方案A：建立角色领域服务（推荐）

```
services/character/
├── CharacterDomainService.ts          ← 统一入口
├── CharacterMapper.ts                 ← 统一序列化/DTO
├── preparation/                       ← 原 characterPrep/
│   ├── CharacterPreparationService.ts
│   ├── CharacterCastGeneration.ts
│   └── CharacterCastQuality.ts
├── resource/                          ← 原 characterResource/
│   ├── CharacterResourceExtractionService.ts
│   └── CharacterResourceLedgerService.ts
├── consistency/                       ← 原 characterConsistency/
│   ├── CharacterConsistencyDetector.ts
│   └── CharacterConsistencyExtractor.ts
├── profile/                           ← 原 characterProfile/
│   └── CharacterVisibleProfileService.ts
├── arc/                               ← 原 novel/characters/
│   └── CharacterArcService.ts
└── exit/                              ← 原 characterExit/
```

**工时**：10-12h
**收益**：
- 7 个目录 → 1 个目录
- 11 处序列化 → 1 个 CharacterMapper
- 统一入口降低调用方复杂度

### 方案B：提取 CharacterMapper（低成本）

不移动目录，仅提取统一的 `CharacterMapper.ts` 到 `services/character/`，将 11 处序列化收敛。

**工时**：4-6h
**收益**：消除序列化重复，目录结构保持不变
