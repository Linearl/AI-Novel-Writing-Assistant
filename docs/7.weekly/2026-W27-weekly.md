## 本周迭代对用户的影响

这一周的重点是让系统变得轻量、可靠和专注：

- **NovelEdit.tsx 从 2731 行拆分到 380 行**（缩减 86%），这意味着小说创作的主工作台页面加载更快、交互更流畅、后续功能迭代风险更低。用户在写长篇时不会因为页面沉重而感到卡顿。

- **Server 超大文件分批拆分**，8 个超过 680 行的服务端文件全部拆分到模块化的子文件，后台 API 响应更稳定，不会因为单文件膨胀导致导出链混乱。

- **漫画/短剧模块移除**，项目聚焦小说创作方向。不再有与小说无关的 UI 入口和后台逻辑占用资源，项目的安装包体积、编译时间和依赖复杂度都相应降低。

- **导演事件系统收敛和循环依赖解耦**，自动导演在运行时的阶段切换更干净，不会出现因为事件丢失导致进度停滞的问题。

## 经验回灌

- **大文件拆分策略**：先提取纯函数 → 再提取子模块 → 最后调整 barrel export，避免一步到位导致大面积 import 失败
- **循环依赖解耦**：接口抽象（IDispatcher）比依赖注入框架更轻量，适合渐进式重构
