# 交接文档：GitHub Release 产物启动崩溃修复（2026-08-12）

> 生成：2026-08-12 | 状态：**修复已完成并本地验证，待推送发布**

## 1. 任务背景

用户要求验证 GitHub 上发布的 v0.1.1 桌面版是否可用。实测下载解包启动后**崩溃**（进程退出、无 UI）。

**最终结论：GitHub 上发布的 v0.1.0 和 v0.1.1 均不可用**（启动即崩）。本地构建产物可用（本地有 dev.db 种子源）。

## 2. 根因链（三层）

1. **表层**：应用启动后进程退出，UI 报 `Cannot find latest.yml`（electron-updater 404）——这是伴随错误，非崩溃根因。
2. **中层**：日志显示 `bootstrap failed. SqliteError: no such table: main.DramaEpisode`——server 空库执行运行时迁移失败。
3. **深层**：
   - CI 干净 checkout **没有 `server/dev.db`**（92MB，gitignore 不入库）→ `clean-dev-db.cjs` 报"输入数据库不存在"→ fallback direct copy 也失败（候选均不存在）→ **asar 内无 `seed-dev.db`**。
   - 运行时 `ensureRuntimeDatabaseReady` 发现无 seed → 在空库上应用迁移链 `migrations.sqlite` → `20260710120000_novel_json_consolidation` 的 `ALTER TABLE "Novel" DROP COLUMN "sourceKnowledgeDocumentId"` 在 SQLite 上失败（**该列含 FK 约束，SQLite 不允许 DROP**，报 P3018 `unknown column "sourceKnowledgeDocumentId" in foreign key definition`）。
   - 本地 dev.db 从未应用过该迁移（`_prisma_migrations` 无记录但表结构已是新态），是演进/折叠状态——**迁移链在干净库上不可用是历史遗留缺陷**。

## 3. 已完成的修复（提交 ff26d97c，未推送）

### 文件 1：`desktop/scripts/stage-desktop.cjs`（+84 行）

- `createSeedDatabase()` 新增分支：当本地 dev.db 候选全部不存在（CI 场景）时调用 `generateSeedDatabaseViaPrisma()`。
- 新增 `generateSeedDatabaseViaPrisma()`：
  1. `pnpm prisma:push`（**db push 按当前 schema 建库，不应用历史迁移链**——这是关键决策，因为 migrate deploy 在干净库必然失败）
  2. `pnpm db:seed` 注入系统内置创作资源（NovelGenre/AntiAiRule/WritingTechnique/StyleTemplate 等）
  3. `clean-dev-db.cjs` 清理用户数据表 → 输出 `desktop/build/app/dist/seed-dev.db`
- 新增 `hasAnyCandidate()` 辅助函数。
- `ensureMigrationsApplied()` 先 `CREATE TABLE IF NOT EXISTS "_prisma_migrations"`（db push 建的库没有此表），再标记全部 67 条迁移为已完成（checksum='seed'）——保证运行时不会重试任何迁移。

### 文件 2：`server/prisma.config.ts`（1 行）

- seed 命令 `ts-node-dev --transpile-only src/db/seed.ts` → `tsx src/db/seed.ts`（server 依赖里只有 tsx，无 ts-node-dev，CI 上原命令会失败）。

### 注意：`pnpm.cmd` 调用必须带 `shell: true`（Windows 上 execFileSync 不能直接执行 .cmd，否则 `spawnSync pnpm.cmd EINVAL`）——已在代码中处理。

## 7. 遗留事项/风险

- **migrations.sqlite 迁移链缺陷**：`20260710120000_novel_json_consolidation` 的 DROP COLUMN（含 FK）在干净 SQLite 上永远失败。本次用 db push 绕过（seed 自带完整结构+全量迁移记录），但**未来任何需要从零建库的路径**（新用户环境、重置数据库）都会踩坑。长期应修复该迁移为重建表方式，或接受 db push 作为标准建库方式。
- seed 生成依赖 `prisma db push` 结果 = 当前 schema——若 schema 与迁移链漂移，seed 结构可能与后续迁移假设不一致（当前一致，已验证）。
