# 决策日志 — REQ-3022 AutoDirector 共享 Stage 组件提取

## 决策 1：方案 A（提取共享 Core）vs 方案 B（合并目录 + 条件渲染）

- **决策点**：采用哪种方式统一两套 Stage 组件
- **方案 A**：在子组件级目录下新建 `shared/` 子目录，提取 Core 组件，两套包装组件引用 Core
- **方案 B**：合并为一个 Stage 组件，在组件内部通过 `layout` 条件渲染不同布局
- **选择**：方案 A — 提取共享 Core 组件
- **理由**：
  - 方案 A 保持了两个入口目录独立，外部消费者无需改动 import 路径
  - Core 组件职责单一，只包含共享逻辑，测试和修改变得聚焦
  - 包装组件极薄（10-20 行），布局差异一目了然，不混在 200 行的条件渲染中
  - 方案 B 会将两套布局混在一个文件内，增加单文件复杂度，且丢失了两套入口的独立表达能力
  - 未来如果新增第三种场景（如移动端专用），方案 A 只需新增一个包装组件，方案 B 需要再嵌套一层条件分支
- **日期**：2026-07-17
- **决策者**：用户确认

## 决策 2：Core 组件放置位置

- **决策点**：Core 组件放在哪个目录
- **选择**：放在 `pages/novels/components/autoDirectorCreate/shared/` 下
- **理由**：
  - 子组件级目录本身就是 components 层级，`shared/` 作为其子目录语义合理
  - `autoDirector/` 是页面级目录，放 shared 组件不合适
  - 两个包装组件都可以从 `../shared/` 相对引用，路径清晰
- **日期**：2026-07-17
- **决策者**：AI 分析

## 决策 3：Props 接口设计方式

- **决策点**：Core 组件 Props 是接收 controller 对象还是摊平原子 Props
- **选择**：摊平原子 Props
- **理由**：
  - 两个入口的 controller 接口不完全相同（页面级多用 hook，子组件级多用 props 注入）
  - 摊平 Props 使 Core 组件与具体 controller 解耦，不依赖任何特定的 hook/controller 类型
  - 包装组件负责从 controller 解构，适配逻辑集中在包装层
  - Core 组件成为纯展示组件，更容易单独理解和测试
- **日期**：2026-07-17
- **决策者**：AI 分析

## 决策 4：布局差异的处理方式

- **决策点**：通过什么机制区分全屏 vs 紧凑布局
- **选择**：统一 `layout` prop（`"fullscreen" | "compact"`）+ 条件 className
- **理由**：
  - 单一枚举值控制所有布局差异，包装组件只需传入一个值
  - 条件 className 处理间距、字号差异，不引入额外技术方案
  - 对于差异较大的区域（如导航按钮），通过可选的 render prop 扩展

- **决策者**：AI 分析
