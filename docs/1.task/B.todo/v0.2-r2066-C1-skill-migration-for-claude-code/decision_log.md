# REQ-2066 决策日志 — Skill 版本迁移

## 决策 1：以 Claude Code 为第一迁移对象

**日期**：2026-07-29
**决策点**：选择哪个平台作为第一迁移目标
**选项**：
1. Claude Code（推荐）
2. Codex
3. 其他编程智能体

**选择**：Claude Code

**理由**：
1. Claude Code 是 Anthropic 官方 CLI，生态更成熟
2. 我们项目已有 `.claude/` 目录和大量 Claude Code 配置
3. Claude Code 的 Skill 支持更完善（SKILL.md + references）
4. 上游 Skill 已验证 Codex 路径，我们可以差异化

**影响**：
- 需要适配 Claude Code 的 Skill 格式
- 可以参考上游 Skill 的结构
- 需要测试 Claude Code 兼容性

**状态**：✅ 已确认

## 决策 2：蒸馏而非重写

**日期**：2026-07-29
**决策点**：如何从当前项目生成 Skill 版本
**选项**：
1. 蒸馏（推荐）：从现有能力中提取核心流程
2. 重写：从零开始实现
3. 复制：直接复制上游 Skill

**选择**：蒸馏

**理由**：
1. 我们有更多能力（Auto-Director、质量检查、写法资产等）
2. 蒸馏可以保留核心流程，去掉运行时依赖
3. 比复制上游 Skill 更完整
4. 比重写更高效

**影响**：
- 需要识别核心能力
- 需要设计蒸馏边界
- 需要保持接口一致

**状态**：✅ 已确认

## 决策 3：不做跨书图谱

**日期**：2026-07-29
**决策点**：是否蒸馏跨书知识图谱能力
**选项**：
1. 不做（推荐）：暂无需求
2. 做：完整蒸馏
3. 部分做：只蒸馏基础能力

**选择**：不做

**理由**：
1. 我们当前项目是单书模式，无跨书需求
2. 跨书图谱是上游 Skill 的独特能力，但我们不需要
3. 蒸馏跨书图谱会增加复杂度
4. 未来有需求时再考虑

**影响**：
- Skill 版本不支持跨书复用
- 可以通过 fork 模式替代
- 不影响核心写作流程

**状态**：✅ 已确认

## 决策 4：分阶段蒸馏

**日期**：2026-07-29
**决策点**：蒸馏的组织方式
**选项**：
1. 分阶段（推荐）：核心 → 增强 → 测试
2. 一次性：全部蒸馏完成
3. 按模块：每个模块独立蒸馏

**选择**：分阶段

**理由**：
1. 核心流程必须先完成
2. 增强能力可以并行
3. 测试需要在完成后进行
4. 分阶段便于管理和回滚

**影响**：
- 阶段一：核心蒸馏（2-3 周）
- 阶段二：增强能力（2-3 周）
- 阶段三：测试验证（1-2 周）

**状态**：✅ 已确认

**日期**：2026-07-29
