# Decision Log — REQ-3023 步骤6批量写作

## D1：后端零改动，复用 Pipeline API

- **日期**: 2026-07-17
- **决策**: 不新增后端 API，直接复用 `POST /novels/:id/pipeline/run`
- **理由**: 该 API 已完全支持按范围批量写作 + autoReview/autoRepair 全流水线，与自动导演使用同一套 PipelineJob 系统
- **替代方案**: 新增专用批量写作 API → 过度设计，增加维护成本

## D2：UI 参照步骤5批量细化模式

- **日期**: 2026-07-17
- **决策**: 复用 `StructuredChapterDetailCard` 的范围选择器交互范式
- **理由**: 用户已熟悉步骤5的交互（连续 N 章 / 可见 / 全卷），保持一致性
- **替代方案**: 勾选章节列表 → 增加操作复杂度，不适合大批量场景

## D3：与自动导演互斥

- **日期**: 2026-07-17
- **决策**: 有活跃自动导演任务时禁用批量写作按钮
- **理由**: 两者都会操作 PipelineJob 和章节数据，并发可能冲突。自动导演有更完整的状态管理
- **替代方案**: 允许并行 → 需要大量冲突检测逻辑，ROI 低
