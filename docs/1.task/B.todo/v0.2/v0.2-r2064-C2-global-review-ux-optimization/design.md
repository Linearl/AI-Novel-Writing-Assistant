# 设计：全局审校用户体验优化

## 三栏布局

```
┌──────────┬─────────────────────────┬──────────────┐
│ 筛选面板  │ 问题列表                 │ 修复进度     │
│          │                         │              │
│ [状态▼]  │ ┌─#G001 严重──────────┐ │ 修复进行中   │
│ [程度▼]  │ │ 角色性格不一致       │ │ ██████░░ 60%│
│          │ │ 第3章 第7章          │ │ 正在修复     │
│          │ └─────────────────────┘ │ 第4/7章      │
│          │ ┌─#G002 高───────────┐ │ 问题         │
│          │ │ 情节断裂            │ │ #G003 #G005 │
│          │ │ 第5章              │ │              │
│          │ └─────────────────────┘ │              │
└──────────┴─────────────────────────┴──────────────┘
```

使用 CSS Grid 实现：`grid-template-columns: 240px 1fr 280px`

## 进度格式

```
正在修复第 3/7 章，包含问题 #G003 #G005 #G008
```

按章节数计算：`progress = completedChapters / totalChapters * 100`

## 状态更新

批量修复 mutation 的 onSuccess 中：
1. invalidateQueries 刷新问题列表
2. 后端 repair 完成后自动将关联问题标记为 fixed
3. 前端刷新后卡片自然更新

## AI复核

问题状态为 `fixed` 时，卡片底部显示"AI复核"按钮。点击后：
1. 调用定向验证 API（仅检查该问题是否真正解决）
2. 验证通过 → 状态变为 `verified`
3. 验证失败 → 状态回退为 `confirmed`，显示失败原因
