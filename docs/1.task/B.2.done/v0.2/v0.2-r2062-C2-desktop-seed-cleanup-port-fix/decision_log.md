# REQ-2062 决策日志

## 决策 1：清理策略

**日期**：2026-07-21
**决策**：使用复制-清理副本方式，不修改原始数据库
**理由**：用户明确要求打包过程不能导致原始数据被清空
**替代方案**：
- 直接清理原始数据库（❌ 否决，用户不接受）

## 决策 2：清理范围

**日期**：2026-07-21
**决策**：清空 137 张表，保留 4 张表
**理由**：
- 清空：用户数据（API Key、小说项目、配置）
- 保留：产品预设（AntiAiRule、WritingTechnique、StyleTemplate）和系统表（_prisma_migrations）
**替代方案**：
- 只清空 APIKey 和 Novel（❌ 否决，AppSetting 也需清空）
- 清空所有表（❌ 否决，产品预设应保留）

---

## 决策 3：清理脚本技术选型

**日期**：2026-07-21
**决策**：使用 better-sqlite3
**理由**：
- 项目已有依赖
- 性能好，可事务批量清理
- 可从 Prisma schema 自动生成清空顺序
**替代方案**：
- sqlite3 CLI（❌ 否决，需手动维护表清单）
- Prisma DB execute（❌ 否决，需启动 Prisma Client）

---

## 决策 4：端口偏移基准

**日期**：2026-07-21
**决策**：基于 Web server 端口 13000 偏移 1250
**理由**：
- 语义清晰：桌面端 = Web 端口 + 1250
- 如果 Web 端口改为其他值，桌面端自动跟随
**替代方案**：
- 基于原 external 默认端口 3000 偏移（❌ 否决，3000 本身就不正确）

---

## 决策 5：Managed 模式端口策略

**日期**：2026-07-21
**决策**：使用固定端口 14250，随机端口作为 fallback
**理由**：
- 端口可预测，便于调试
- 避免每次启动端口不同导致的困惑
**替代方案**：
- 保持随机端口（❌ 否决，用户希望端口固定）
