# 决策日志 — REQ-7083 Character Service Consolidation

## 决策 1：方案选择（方案 A vs 方案 B）

- **决策点**：角色代码收敛方案
- **选择**：方案 A — 建立角色领域服务（`services/character/` 作为统一入口）
- **备选方案**：方案 B — 保持各目录独立，仅消除序列化碎片（不迁移目录）
- **理由**：
  - 方案 A 一次性解决目录分散和序列化碎片两个问题
  - 统一入口降低后续维护认知负担
  - 符合项目的模块化收敛方向（`app/` → `platform/` → `modules/`）
  - 预计工时 10-12h，在可接受范围内
- **日期**：2026-07-17
- **决策者**：用户确认

## 决策 2：内联 Prompt 处理策略

- **决策点**：23 处内联 prompt 如何处理
- **选择**：在本任务中一并处理（未决，待确认）
- **备选方案**：单独另开任务包处理 prompt 迁移
- **分析**：
  - 一并处理：减少一次迁移的导入路径变更回合；但增加本任务复杂度
  - 单独处理：本任务聚焦目录和序列化收敛；prompt 迁移可并行进行
- **建议**：一并处理，因为 `characterPreparationSupplemental.ts` 的 13 处 prompt 在迁移 preparation 目录时必然触及，分两次改同一批文件效率低
- **日期**：2026-07-17
- **决策者**：待确认

## 决策 3：CharacterMapper 文件组织

- **决策点**：CharacterMapper 是独立文件还是合并到 CharacterDomainService
- **选择**：独立文件 `CharacterMapper.ts`（未决，待确认）
- **理由**：
  - 独立文件：职责清晰（序列化 vs 业务编排），便于单独测试，符合单一职责原则
