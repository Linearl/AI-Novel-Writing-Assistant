# 决策日志 — REQ-7077 超大文件拆分

## 决策 1：拆分优先级

- **决策点**：3 层的拆分顺序
- **选择**：P1 Shared → P2 Server → P3 Client
- **理由**：Shared 类型是 Server 和 Client 的共同依赖，更改 Shared 后须先验证构建再推进到上层，降低级联错误风险
- **日期**：2026-07-17
- **决策者**：AI 分析 + 用户确认

## 决策 2：Facade 模式

- **决策点**：拆分后调用方是否需更新 import 路径
- **选择**：使用 facade（原文件 re-export 子模块）保持对外接口不变
- **理由**：最小化调用方改动，通过 TypeScript 编译器确保 re-export 完整性。仅在循环依赖等特殊情况下更新调用方 import
- **日期**：2026-07-17
- **决策者**：AI 分析

## 决策 3：拆分粒度

- **决策点**：拆分目标行数
- **选择**：目标 ≤600 行/文件，子模块 ≤400 行
- **理由**：遵循项目约定（目标 ~600 行，>700 必须重构），子模块控制在 400 行以内确保后续维护性
- **日期**：2026-07-17
- **决策者**：AI 分析
