# 章节生产

在规划、起草、继续、审查或修复章节时读取本页。

## 1. 首章前确认门槛

生成第一章正式计划或正文前，读取 `novel-brief.md` 的确认记录。叙事视角、节奏与语言倾向、单章长度和内容边界必须是 `用户确认` 或 `用户授权 AI 决定`；如仍未决，每轮只询问其中最影响正文的 2–3 项并提供推荐。

## 2. 章节计划合同

在 `plan.md` 中保持同一份合同，供写作、验收和修复共同消费。

### 2.1 基本任务

- 本章即时目标；
- 主要阻力；
- 参与角色及各自作用；
- 必须推进的剧情和信息；
- 必须保留的事实与优势；
- 必须触碰的伏笔或承诺；
- 必须发生的角色目标变化；
- 参与角色的当下呈现：本章可见身份、衣着/伤病/气色、可用物件、行为或声音锚点，以及不得误写的状态；
- 本章调用的世界规则、势力和舞台 ID，以及它们造成的准入、资源、信息或行动限制；
- 可以延后的事项；
- 禁止越过的边界。

### 2.2 读者体验

- 读者进入本章时最关心的问题；
- 本章可见回报及强度：`setup`、`partial` 或 `major`；
- 主角即时欲望；
- 关键转折；
- 情绪位移；
- 信息交付；
- 章末相对章初的净变化；
- 继承的旧钩子责任；
- 新的章末牵引。

### 2.3 章节节奏段与篇幅预算

每份 `plan.md` 都必须写入一份可执行的篇幅合同；没有用户特别指定时，继承 `novel-brief.md` 的书级默认值。

- 目标字数：例如 `3000`；
- 可接受区间：例如 `2500–3500`；
- 预算来源：书级默认 / 用户固定 / 本章经批准的例外；
- 本章为何需要该长度；
- 最低有效内容：即使接近下限也必须完成的事件、回报、转折和章末钩子；
- 超出上限时优先删减的内容；
- 未达下限时只能补入的新内容类型。

在场景预算前，先设计 3—5 个**章节节奏段**。每一段都写明：进入状态、主角动作与阻力、信息或关系变化、读者回报/情绪、离场状态和字数预算。

## 3. 写作上下文优先级

按优先级读取：

1. 本章计划与义务合同；
2. 上一章实际尾段；
3. 角色硬事实与参与角色的当下呈现；
4. 禁止越界与受保护揭示；
5. 当前卷窗口和节奏段职责；
6. 当前场景涉及的世界规则、势力状态和舞台限制；
7. 相关未兑现承诺和资源状态；
8. 风格合约和参考写法。

## 4. 上下文清单

连续性已启用时，在 `chapters/chapter-XXX/context-package.md` 中为本章建立简明清单：

- 本章目标、稳定正文来源与当前卷窗口；
- 已选权威文件和每个文件的用途；
- 必需约束（事实、角色身份与当下呈现、禁止越界、直接钩子、资源风险，以及实际调用的世界条目 ID 和限制）；
- 因无关、重复或超出窗口而裁掉的内容；
- 缺失的硬约束与保守处理方式。

## 5. 生成与审查

### 5.1 正文生成

- 生成整个章节作为一篇连贯草稿
- 使用场景节拍进行规划和针对性修复
- 默认运行一次中文小说人性化处理

### 5.2 审查流程

1. 检查章节合同完成度
2. 检查连续性一致性
3. 检查文风和节奏
4. 记录质量问题

### 5.3 修复流程

按以下升级顺序：

1. 接受可用内容
2. 记录非阻塞性质量债务
3. 应用针对性补丁
4. 仅在本地修复无法满足合同时重写
5. 仅在章节职责本身不可能或错位时推荐重规划

## 6. 状态回灌

章节正文验收后：

1. 更新 YAML 连续性事实
2. 更新受影响的角色资产
3. 更新质量债务
4. 更新恢复记录
5. 更新状态索引
